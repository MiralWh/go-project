# Основные команды Git

Git — распределённая система контроля версий.

## 1. Настройка

Перед началом работы необходимо представиться:

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "your.email@example.com"
```

Просмотр всех настроек:

```bash
git config --list
```

## 2. Создание репозитория

| Команда | Описание |
|---------|----------|
| `git init` | Инициализировать новый локальный репозиторий в текущей папке |
| `git clone <url>` | Склонировать удалённый репозиторий на компьютер |

## 3. Основные операции

| Команда | Описание |
|---------|----------|
| `git status` | Показать состояние рабочей директории и индекса |
| `git add <файл>` | Добавить указанный файл в индекс (отслеживание изменений) |
| `git add .` | Добавить все файлы и папки текущей директории в индекс |
| `git add -A` | Добавить все изменения (включая удаления) во всём репозитории |
| `git commit -m "Сообщение"` | Зафиксировать изменения с комментарием |
| `git commit -am "Сообщение"` | Добавить все отслеживаемые файлы и сразу зафиксировать |
| `git log` | Показать историю коммитов |
| `git log --oneline` | Краткая история коммитов (по одной строке) |
| `git diff` | Показать различия между рабочей директорией и индексом |
| `git diff --staged` | Показать различия между индексом и последним коммитом |

## 4. Ветвление и слияние

| Команда | Описание |
|---------|----------|
| `git branch` | Показать список веток |
| `git branch <имя>` | Создать новую ветку |
| `git checkout <ветка>` | Переключиться на указанную ветку |
| `git checkout -b <ветка>` | Создать и сразу переключиться на новую ветку |
| `git switch <ветка>` | Переключиться на ветку (современная альтернатива checkout) |
| `git switch -c <ветка>` | Создать и переключиться на новую ветку |
| `git merge <ветка>` | Слить указанную ветку с текущей |
| `git branch -d <ветка>` | Удалить ветку (если она слита) |
| `git branch -D <ветка>` | Принудительно удалить ветку |

## 5. Удалённые репозитории

| Команда | Описание |
|---------|----------|
| `git remote add origin <url>` | Привязать удалённый репозиторий с именем `origin` |
| `git remote -v` | Показать список удалённых репозиториев |
| `git push -u origin <ветка>` | Отправить ветку на удалённый репозиторий и запомнить связь |
| `git push` | Отправить изменения в удалённый репозиторий |
| `git pull` | Получить изменения из удалённого репозитория и слить с текущей веткой |
| `git fetch` | Получить изменения из удалённого репозитория без слияния |

## 6. Отмена изменений

| Команда | Описание |
|---------|----------|
| `git restore <файл>` | Отменить изменения в файле (вернуть к последнему коммиту) |
| `git restore --staged <файл>` | Убрать файл из индекса (отменить `git add`) |
| `git reset --soft HEAD~1` | Отменить последний коммит, оставив изменения в индексе |
| `git reset --mixed HEAD~1` | Отменить последний коммит, оставив изменения в рабочей директории |
| `git reset --hard HEAD~1` | Полностью отменить последний коммит и все изменения |
| `git revert <commit>` | Создать новый коммит, отменяющий указанный |

## 7. Временное сохранение изменений (stash)

| Команда | Описание |
|---------|----------|
| `git stash` | Спрятать текущие изменения, чтобы вернуться к чистому состоянию |
| `git stash list` | Показать список спрятанных изменений |
| `git stash pop` | Вернуть последние спрятанные изменения и удалить их из стека |
| `git stash apply` | Вернуть изменения, оставив их в стеке |
| `git stash drop` | Удалить последнее спрятанное изменение |

## 8. Игнорирование файлов

Создайте файл `.gitignore` в корне репозитория и перечислите в нём шаблоны файлов и папок, которые не нужно отслеживать:

```
# Пример .gitignore
node_modules/
*.log
.env
dist/
```

## 9. Теги

| Команда | Описание |
|---------|----------|
| `git tag` | Показать список тегов |
| `git tag v1.0.0` | Создать лёгкий тег |
| `git tag -a v1.0.0 -m "Версия 1.0.0"` | Создать аннотированный тег |
| `git push origin --tags` | Отправить все теги на удалённый репозиторий |

## 10. Полезные советы

- Делайте коммиты часто и с осмысленными сообщениями.
- Перед началом работы над новой функцией создавайте отдельную ветку.
- Регулярно делайте `git pull`, чтобы синхронизироваться с удалённым репозиторием.
- Используйте `.gitignore`, чтобы не добавлять в репозиторий лишние файлы.
- Для просмотра истории в удобном виде используйте `git log --oneline --graph --all`.

---

**Основные сокращения:**
- `HEAD` — указатель на текущий коммит.
- `origin` — стандартное имя удалённого репозитория.
- `master` / `main` — основная ветка (в новых репозиториях обычно `main`).
